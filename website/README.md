# Mystery Quest website

This folder contains the project's website: its source files, the build tools, the
generated ruleset documents, and the planning documents.

## What the website is

A plain static site presenting the Mystery Quest ruleset: the full rules with a
searchable outline, a Moves browser with filters, and a character creator (player
characters and NPCs, with JSON export/import) plus an editor for custom Moves.
Everything runs locally in the browser and stores its data in `localStorage` — no
accounts, no server, no runtime dependencies. The pages use a per-page `<base>` tag
and relative URLs, so the built site works both at a domain root and under a project
subpath (`user.github.io/<repo>/`).

## Layout

- **`site/`** — the website's source files, committed to the repository: the
  hand-written pages (`index.html`, `about/`, `links-and-downloads/`, `moves/`,
  `creator/`), the styles and scripts in `assets/css/` and `assets/js/`, the images
  in `assets/images/`, and the hand-maintained data in `assets/data/`:
  `moves.json`, the site's Move list. It is edited directly in the repo.
- **`dist/`** — the built, ready-to-serve site. Entirely generated by
  `tools/build.mjs`, which copies `site/` as-is (minifying `assets/data/moves.json`
  on the way out) and adds the generated rules page (search index and version data
  embedded inline) and the license copies. Gitignored as a whole — never commit
  it, never edit it.
- **`ruleset/`** — the ruleset documents the build consumes, generated by
  `tools/update-ruleset.mjs` from the newest export in `../rules/`. Never hand-edit
  them; see [the ruleset README](ruleset/README.md).
- **`tools/`** — `build.mjs` (builds `dist/` from `site/` + `ruleset/`),
  `watch.mjs` (re-runs the build automatically on source changes, for local
  development), `update-ruleset.mjs` (regenerates `ruleset/` after a new export
  lands in `../rules/`), and the rules page template in `templates/`.
- **[the content plan](CONTENT_PLAN.md), [the technical plan](TECHNICAL_PLAN.md), [the design reference](design.md), `design-reference/`** —
  planning documents and design screenshots.

## Local development

Requires Node.js v26 for the build (the version CI uses; the built site itself is
dependency-free).

1. Build the site — once:

       node tools/build.mjs        # from this folder, or: node website/tools/build.mjs from the repo root

   Or keep `dist/` up to date automatically while you edit. The watch script runs
   the same build on startup and after every change to the watched sources —
   `site/`, `ruleset/`, `tools/templates/` and the repo-root `LICENSE`/[the licensing notes](../LICENSING.md)
   (stop it with Ctrl+C):

       node tools/watch.mjs        # from this folder, or: node website/tools/watch.mjs from the repo root

   Either way, `dist/` is built from `site/` and `ruleset/`.

2. Serve `dist/` with any static file server and open it in a browser:

       cd dist
       python3 -m http.server 8000
       # or: npx serve ..

   Then open http://localhost:8000/.

After a new ruleset export arrives in `../rules/`, regenerate the ruleset documents
first (`node tools/update-ruleset.mjs` from this folder); the watch script picks the
change up automatically, otherwise re-run the build.

## Deployment

Pushing to `main` deploys automatically: `.github/workflows/website-workflow.yml`
runs `tools/build.mjs` after checkout on an `ubuntu-26.04` runner with Node.js 26
(`actions/setup-node`) and publishes `website/dist/` to GitHub Pages.
