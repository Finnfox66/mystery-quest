# Website ruleset

This folder holds the **ruleset documents used by the website**, generated by
`Website/tools/update-ruleset.mjs` from the latest ruleset export in `Rules/`
(run the script whenever a new export arrives). Never hand-edit the generated
documents — changes to the rules belong in the author's Google Doc (the source
of truth), and the raw exports in `Rules/` are never modified.

Contents:

- **`Mystery Quest ruleset.md`** — the artifact-cleaned ruleset, under a
  generic name so references to it never change. It does **not** include the
  Example Move conversions section (the website provides the Moves list
  separately) or the **Contents and material** section (the document's own
  table of contents, links to material, acknowledgments and character-sheet
  image — the site presents its contents listing and material links
  separately, if at all). The document byline's placeholder version ("0.9.5+") is
  rewritten to the true version derived from the export filename. The
  document keeps its head (title, subtitle line, byline) for standalone
  completeness — the v2 Markdown download needs it — but the rules web page
  renders from the first "## Description" heading onward (the page header,
  version banner and footer present the name, author and version instead).
- **`example-move-conversions.md`** — the cleaned Example Move conversions
  section on its own; the build's source for `moves.json`.
- **`version.json`** — the true ruleset version (derived from the export
  filename, e.g. `0_9_6_0.md` → `0.9.6.0`), the source export name and the
  update date. The site's version banner reads the version from here — never
  from the document byline, which the author keeps as a placeholder.
- **`images.json`** — the **image manifest**: it specifies what each image
  link in the ruleset represents. For each export image reference (`image1`,
  …) it gives the alt text, the website asset path to serve it from, and
  optionally a repo source file the script copies into
  `Website/site/assets/`. If a future export carries a base64 payload for a
  reference instead, the script extracts it into the assets automatically.
  A reference with no manifest entry fails the script run loudly — new images
  must be given a manifest entry here. Entries remain valid even when their
  reference no longer appears in the generated rules copy: the
  character-sheet image's reference lived inside the removed "Contents and
  material" section, but the manifest still copies the asset to
  `Website/site/assets/images/character-sheet.png`, where the site uses it
  directly by path (it is placed on the site's Links and downloads page —
  CONTENT_PLAN.md §2.6 — instead of inside the rules text).
